# ADR-0014: Ocean-frame falloff — no landmass clips the map edge

- **Status:** Accepted (backfilled)
- **Date:** 2026-08 (decision predates ADR system)
- **Touches:** `game/rust/src/geo.rs` (frame pass), `lib.rs` size guard

## Context

Continents generated by noise + radial bulges regularly ran off the map
border, reading as a cropped screenshot rather than a world. Toponymy also
suffered: labels for edge-clipped features anchored at cut centroids.
Wrapping (torus world) was considered and rejected — every downstream
system (advection, flow routing, A*, naming, rendering) would pay wrap
complexity forever.

## Decision

The final terrain pass multiplies height by a smoothstep frame that sinks
elevation toward deep ocean within ~10 % of every border (with a hard sink
in the outer ~1 %), guaranteeing zero land cells on the border. The map is
a *complete* world: everything nameable lies fully inside the frame. The
world was also widened (640×512 default) so the frame does not crowd the
continents.

## Consequences

- Harness check `border land cells == 0` holds on every seed; labels and
  territories never anchor off-map.
- The map reads as an atlas plate — a whole known world with ocean margins.
- Costs: no circumnavigation stories and a soft bias toward central
  continents; accepted as the identity of the product (a chronicle of one
  known world, not a globe).

## Alternatives considered

- **Toroidal wrap** — permanent complexity tax on every field and path
  algorithm, plus unrenderable seam in a flat atlas presentation.
- **Cylinder wrap (east-west only)** — halves the tax but keeps the seam
  and still complicates advection and routing.
- **Let land clip** — the status quo this replaced; consistently read as a
  bug in user tests of the map's believability.
